Observed browser playback-stop acknowledgements were 182/256 ms after barge-in in the two Nano sessions and 139 ms on Thor. These are individual smoke-test observations, not latency guarantees or evidence that GPU work stopped at that instant. The next Thor LLM request began about 1 ms after ASR finalization. A first Nano synthesis took 3.154 s, while later short synthesis took about 0.323 s; the data does not establish the cause of that first-request delay.

For short responses, a browser first-playback marker can occur after the server's TTS-complete event. That reflects generation completion preceding browser playback, not necessarily missing streaming or an incorrect TTFA measurement. Keep server first-audio latency and audible-playback latency distinct.

An earlier Thor diagnostic session showed a backend TTS cancellation completing approximately 22 ms before the browser playback-stop acknowledgement. A later turn completed TTS successfully. Two subsequent LLM completions contained reasoning and an empty answer, so no synthesis was requested. Regression tests cover the event-order race and the distinct empty-answer condition; this is not evidence that the shared LLM server's generation issue is resolved. This earlier diagnostic session is separate from the passing final-candidate tests above.

The Japanese failure was a provider `ValueError` rejecting `ja-JP`, after the small Whisper model loaded successfully. The REST adapter normalizes this field at the request boundary rather than changing the Riva configuration schema.

Map USB/Riva and NVIDIA open-model regression evidence to exact relevant commits, or mark it as untested/accepted limitation. Keep private host/session data and internal security approval links outside the public repository.

## Fixed-input provider investigation

Two real Japanese microphone WAVs (1.920 s and 2.816 s) were captured byte-for-byte at the REST request boundary. No raw audio or private session JSON is committed. For the 2.816 s input, ASR HTTP latency over five runs per condition was median/max: ASR-only 0.385/0.410 s, TTS-overlap 0.483/0.501 s, immediately post-TTS 0.361/0.758 s. For the 1.920 s input, the corresponding values were 0.354/3.704 s, 0.438/4.372 s, and 0.346/3.655 s. All responses were HTTP 200 and transcripts were consistent within each input.

A separate cold request took 4.785 s, of which the provider log attributed 4.32 s to model reload. Do not conflate that case with the warm outliers. Standalone Faster-Whisper/CTranslate2 profiling, without MMAS or TTS, reproduced outliers inside encoder/generation calls with either beam size 5 or 1. Eager CUDA module loading did not remove them. A CUB allocator experiment did not complete its first transcription within the short diagnostic window and was terminated; it is not an accepted workaround. The serving container configuration was not changed by these isolated process experiments. The recommended production defaults remain unchanged; carry the unresolved tail latency as an explicit limitation or resolve it before making bounded-latency claims.
