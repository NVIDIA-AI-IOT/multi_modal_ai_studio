# Voice AI Workbench 0.2.0

Draft release notes; this file does not announce that publication has completed.

Voice AI Workbench brings local speech and optional vision assistants into one configurable UI, with a timeline for understanding recognition, generation, playback, interruption, and device utilization.

This is the new public name for **Multi-modal AI Studio (MMAS)**. The PyPI distribution and recommended CLI are `voice-ai-workbench`. The GitHub repository and Python import remain `multi_modal_ai_studio`, and the old `multi-modal-ai-studio` CLI remains available. Existing settings and session formats are preserved. When replacing an earlier MMAS wheel, use a fresh environment or follow the [upgrade instructions](../development/releasing.md#upgrading-an-earlier-mmas-installation).

## What's new

- **A small-device quick start:** Speaches Faster-Whisper + Kokoro with text-only Gemma 4 E2B, including an Orin Nano path and independent model-service launchers. No Riva entitlement or hosted inference account is required for that path.
- **Interchangeable services:** OpenAI-compatible REST and Realtime speech adapters, NVIDIA Nemotron ASR/Magpie reference services, and the existing Riva gRPC integration. Compatibility and streaming capabilities depend on the selected provider.
- **A conversation workbench:** Model/voice discovery, voice preview, speech speed, optional compact configuration, and presets.
- **Inspectable sessions:** Timeline lanes for speech/VAD, ASR, LLM, TTS, playback and barge-in; recorded host/device configuration, thumbnails, and downloadable session JSON.
- **Two device paths:** Start with the client browser's microphone/speaker, then evaluate server-local USB audio for robot or headless deployments. Browser testing does not qualify a physical robot, acoustic setup, or USB device.
- **Packaging:** Wheel and sdist include the UI and presets. GitHub release assets include checksums and dependency manifests; enabled stable releases promote the same wheel/sdist to PyPI through GitHub Actions and a protected publishing environment.

## Installation

After publication, download the wheel and `SHA256SUMS` from this release, verify the artifact, and install the local wheel in a Python 3.11+ virtual environment. If all release assets are downloaded together, use `sha256sum -c SHA256SUMS`.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install ./voice_ai_workbench-0.2.0-py3-none-any.whl
voice-ai-workbench --version
voice-ai-workbench --preset speaches-jetson --port 8092
```

Once the PyPI job has succeeded, the equivalent installation is `python -m pip install voice-ai-workbench==0.2.0`. Do not claim PyPI availability before checking the published project/version.

The UI requires separately running ASR/LLM/TTS endpoints for conversation. Model weights and containers are **not** inside the wheel. Use the `v0.2.0` repository checkout's [quick start](../../README.md#-quick-start) for the Speaches/Gemma launchers. Existing Riva and NVIDIA open-model launchers remain optional alternatives.

## Known limitations

- The pinned Jetson Speaches container is a release candidate. Backend containers and their release/security lifecycle are separate from this Python package.
- Speaches Realtime Faster-Whisper transcription is VAD-delimited utterance processing; it does not imply model-native partial transcription.
- The pinned Speaches rc3 Realtime ASR path failed concurrent Nano conversation testing. A local backend correction passed controlled load/reconnect, synthetic-microphone browser tests, and a short human-confirmed AirPods conversation, but it has not been published. The recommended REST path has separate validation; installing the updated Workbench wheel alone does not correct the old Realtime server.
- Starting TTS before the LLM finishes reduces waiting via text chunking. Small chunks can reset prosody, and insufficient generation throughput or shared GPU contention can cause pauses. Disable this option for a baseline quality comparison.
- Warm ASR latency outliers were reproduced outside MMAS; this release does not promise bounded latency. Model loading can also make the first response slower.
- An 8 GB device needs sufficient memory headroom and may benefit from swap during CPU-side model loading. Swap does not increase available GPU memory.
- USB/headless and provider-specific integrations, including Qwen3-TTS, have narrower validation than the recommended browser path. The corrected Speaches Realtime and NVIDIA Speech REST conversations were checked with AirPods, and the tester also reported a successful NVIDIA Speech Realtime conversation. Room-speaker acoustic echo and long-session reliability remain separate qualification boundaries.
- Endpoints are intended for trusted development networks. Do not expose unauthenticated model/UI services to the public internet.
- A successful scan with no package inventory is not a security clearance. Confirm the release dependency inventory and disposition of findings separately from functional tests.
